# Понятия базы знаний OSTIS Assistant

## 1. Основы формализации на SC-коде (ostis_knowledge)

### Базовые понятия
- **SC-код** — язык семантического кодирования знаний (Semantic Code). Представляет знания в виде семантической сети (SC-конструкции).
- **sc-элемент** — базовый элемент SC-кода (узел или дуга). Из sc-элементов строятся sc-конструкции.
- **sc-конструкция** — произвольная связная совокупность sc-элементов (подграф SC-памяти).
- **sc-множество** — неупорядоченная совокупность sc-элементов одного типа (понятие). В SC-коде задаётся дугами принадлежности (класс — элемент).
- **sc-структура** — модель/представление некоторой сущности. Формально — подграф с общим корневым узлом.
- **sc-текст** — линейное представление sc-конструкции на внешней среде (бумага, экран).
- **sc-знание** — знание, формализованное в SC-коде (знаковая конструкция, имеющая смысл).
- **sc-файл** — фрагмент SC-памяти, сохранённый во внешней памяти.
- **sc-идентификатор** — уникальное имя sc-элемента в рамках некоторой предметной области (системный идентификатор).

### Внешние представления SC-кода
- **SCg-код** — графическое представление SC-кода (узлы — геометрические фигуры, дуги — стрелки).
- **SCs-код** — строковое (текстовое) представление SC-кода. Используется в .scs-файлах. Основан на тройках `субъект — коннектор — объект`.
- **SCn-код** — гипертекстовое представление SC-кода. Основан на SC-текстах с перекрёстными ссылками.

### Проект OSTIS
- **OSTIS** — Open Semantic Technology for Intelligent Systems. Открытая технология проектирования интеллектуальных систем, основанная на SC-коде и семантических моделях знаний.
- **Классификатор** — компонент интеллектуальной системы, определяющий класс входящего сообщения для выбора соответствующего обработчика (продукции или агента).
- **Продукция** — правило вида «ЕСЛИ (условие) ТО (действие/ответ)». Реализует продукционную модель представления знаний.
- **Семантическая сеть** — модель представления знаний в виде графа (узлы — понятия, дуги — отношения между ними).

## 2. Искусственный интеллект (topic-1-ai-concepts)

- **Искусственный интеллект (ИИ)** — свойство интеллектуальных систем выполнять творческие функции, традиционно считающиеся прерогативой человека.
- **Интеллект** — способность системы адаптироваться к изменениям среды, решать задачи и обучаться.
- **Интеллектуальная система** — техническая/биологическая система, способная решать интеллектуальные задачи, обучаться и взаимодействовать с окружением.
- **База знаний** — база данных, содержащая формализованные знания о предметной области (факты + правила вывода).
- **Решатель задач** — компонент интеллектуальной системы, обеспечивающий поиск решения на основе знаний.
- **Модель представления знаний** — формальный язык/нотация для описания знаний (логическая, продукционная, фреймовая, сетевая).
- **Решение задач** — процесс поиска решения с использованием знаний и логического вывода.

## 3. Направления ИИ (topic-2-ai-directions)

- **Connectionist AI (коннекционизм)** — подход на основе нейронных сетей и глубокого обучения. Имитирует работу мозга (биомиметический подход).
- **Symbolic AI (символьный ИИ)** — подход на основе логики, правил и манипуляции символами. Хорошо интерпретируем.
- **Hybrid AI (гибридный ИИ)** — комбинация символьного и коннекционистского подходов для совмещения обучаемости и интерпретируемости.

## 4. Системные понятия (работа бота)

### Классы пользователей
- **concept_student** — класс учащихся (студент, зарегистрированный в БЗ). Имеет доступ к учебным темам и материалам.
- **concept_user** — класс зарегистрированных пользователей (общий).
- **concept_unknown_user** — класс новых/неизвестных пользователей. При первом сообщении бот регистрирует такого пользователя как `concept_student`.
- **concept_known_user** — флаг «пользователь известен системе». Связывает `myself` с пользователем через `nrel_known_user`.

### Классы сообщений
- **concept_message_topic** — класс тем сообщений. Каждое намерение пользователя описывается отдельным классом, наследующим `concept_message_topic`.
- **concept_student_message**_* — классы сообщений от студентов: приветствия, запросы о понятиях, темах, дисциплинах, библиотеках, навыках.
- **concept_unknown_message**_* — классы сообщений от неизвестных пользователей (приветствие, предложение зарегистрироваться).
- **concept_system_reply_message** — класс ответного сообщения системы.
- **concept_system_reply_message_with_question** — класс ответа с уточняющим вопросом.

### Классы ответов пользователя
- **concept_student_positive_reply_message** — положительный ответ («да», «хочу», «расскажи»).
- **concept_student_negative_reply_message** — отрицательный ответ («нет», «не хочу», «потом»).

### Служебные сущности
- **myself** — узел, представляющий саму систему (Нику). Используется как автор ответов и субъект отношения `nrel_known_user`.
- **concept_intelligent_system** — класс интеллектуальных систем (включает `myself`).
- **concept_skill** — класс навыков системы. Экземпляры: `.process_disciplines` (работа с дисциплинами), `.process_materials` (работа с понятиями), `.help_students` (помощь студентам).

### Навыки системы
| Системный идентификатор | Назначение |
|------------------------|------------|
| `.process_disciplines` | Обработка запросов по дисциплинам и темам |
| `.process_materials` | Обработка запросов по понятиям и материалам |
| `.help_students` | Общая помощь студентам |

### Продукции (правила ответов)
- **nrel_reply_production** — класс продукции (правила). Продукция — правило «ЕСЛИ (условие в БЗ выполняется) ТО (сформировать ответ)».
- **nrel_reply_production_chain** — упорядоченная цепочка продукций для темы сообщения. Порядок от самой специфичной к самой общей (fallback в конце).
- **nrel_corresponding_skill** — навык, соответствующий теме сообщения.
- **nrel_entity_class_descriptions** — какие сущности извлекать из сообщения (становятся входными параметрами продукций).

### Классификация сообщений
- **MessageClassifier** — Python-классификатор (в `TopicInfoAgent`). Определяет класс сообщения по ключевым фразам и паттернам.
- **nrel_message_keywords** — ключевые слова для классификации (задаются в SCS-файле темы).
- **nrel_message_patterns** — regex-шаблоны для классификации.

## 5. Python-библиотеки (py_libraries)

- **sc-client (py-sc-client)** — Python-клиент для подключения к SC-машине через WebSocket. Предоставляет `ScClient`, `ScAddr`, `ScTemplate`, методы `search_by_template`, `generate_elements`, `create_elementary_event_subscriptions`.
- **sc-kpm (py-sc-kpm)** — библиотека для создания sc-агентов и модулей на Python. Содержит `ScServer`, `ScModule`, `ScAgentClassic`, `ScKeynodes`, утилиты генерации/поиска.
- **ScServer** — точка входа для Python-приложения: подключается к SC-машине по WebSocket, управляет модулями и агентами.
- **ScModule** — модуль, группирующий родственные sc-агенты. Регистрируется на сервере.
- **ScAgentClassic** — базовый класс агента. Реагирует на события (действия) в SC-памяти. Жизненный цикл: инициализация → обработка события → завершение действия.
- **ScKeynodes** — реестр предопределённых узлов SC-памяти по системным идентификаторам. Позволяет получать `ScAddr` по имени (например, `ScKeynodes["concept_student"]`).
